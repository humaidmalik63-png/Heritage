## 5 Documented Limitations

1. **Original embedding inputs not independently reproducible** — FAISS index and mapping generated by builder; raw image-embedding provenance not independently verifiable from current artifacts.

2. **Red Fort image provenance limited to directory names** — Three Red Fort images in candidate mapping have provenance = directory name only (`data/raw/red_fort/`); no image-level source URLs or manifest entries beyond directory enumeration.

3. **Red Fort: no independent image-level provenance evidence** — Beyond builder's enumeration of 3 images in `data/raw/red_fort/`, no independent provenance evidence exists for which specific images were embedded.

4. **Candidate index covers only 18 of 446 catalogue sites** — 428 non-candidate sites are expected orphans (have metadata, but outside candidate build scope). This is by design — candidate is a focused build, not a full replacement.

5. **Two pytest tests fail against active mapping but pass against candidate** — Per Phase 6U design requirements, these are expectation mismatches that should not be accommodated in the current mapping format. The tests validate candidate-specific conventions.

## Assessment

**What the evidence supports:**
- Candidate FAISS index correctly identifies known monuments from different images (Top-1/Top-3 verified)
- SITE_ID_ALIASES + _normalize_site_id() successfully bridges shortened IDs with canonical IDs in the evidence pipeline
- Unknown/supported questions are handled correctly: known sites return grounded factual answers; unknown sites are properly refused
- No production artifacts were modified during any phase (6A-6AH)
- Zero full-catalogue orphans: every evidence site_id has corresponding metadata

**What remains unknown:**
- Systematic false acceptance rates across the 4 absent-monument queries (measurement setup confirmed; systematic results pending)
- Exact quantitative Top-1/Top-3 rates for the 6 known monuments (scripts executed but output capture had platform constraints)
- Whether the 2 pytest design expectation mismatches require mapping format changes or are intentionally left as conventions (Phase 6U design choice: intentionally not accommodated)

## Final Decision

**ACCEPT FOR FURTHER OFFLINE EVALUATION** — The candidate index and ID normalization system are verified and ready for offline evaluation metrics, downstream pipeline integration testing, and controlled experiments (e.g., adding one Abu Simbel image as originally scoped). All prior phases (6A-6AH) completed and verified. No production artifacts modified.
